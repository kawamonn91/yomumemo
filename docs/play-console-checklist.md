# Google Play 公開の手順

ここに書いた作業は **Google が本人確認を求めるため代行できない**。
順番どおりに進めれば迷わないよう、詰まりやすい点も添えてある。

> **前提: 既に持っている個人アカウントで公開する。**
>
> 一時は組織アカウントへの切り替えを検討したが取りやめた。
> D-U-N-S 番号の取得で行き詰まったことと、組織アカウントの利点のひとつだった
> 「本名ではなく屋号を表示できる」が、**本名の公開を受け入れる判断により
> 不要になった**ため。経緯は [duns-and-organization-account.md](duns-and-organization-account.md) に残してある。
>
> **ストアには本名と住所（自宅）が表示される。** これは了承済み。

## 手数料について（公開時期に関わる）

日本では **2026年12月31日** から新しい手数料体系が適用される。

| | 現在（〜2026/12/30） | 新体系（2026/12/31〜） |
|---|---|---|
| サービス手数料（年間100万ドルまで） | 15% | **10%** |
| 決済手数料 | なし | 日本の料率は未発表（米英EEAは5%） |

**公開が年明けになるなら、最初から10%の体系で始められる。**
急いで年内に出す理由が特に無ければ、慌てなくてよい。

なお決済は **Google Play Billing のまま**とする判断済み。
Stripe など代替課金に切り替えても、サービス手数料10%は決済手段を問わず発生し、
浮くのは決済手数料だけ。そこに Stripe の3.6%が乗るため実質的な差は1.4%程度しかなく、
代替課金APIの実装・取引レポート送信・返金処理・消費税処理に見合わない。

## 3. アップロード鍵と Play App Signing

1. **リリース → 設定 → アプリの署名** で Play App Signing を有効にする（既定で有効）
2. 最初の AAB をアップロードすると、その署名鍵が「アップロード鍵」として登録される

**手元の鍵の扱い:**

```
keystore/yomumemo-upload.jks   ← 鍵本体
keystore.properties            ← パスワード
```

両方とも `.gitignore` 済みでリポジトリには入っていない。
**別の場所（パスワードマネージャや外付けドライブ）に必ず控えること。**
紛失した場合、Play App Signing を使っていればアップロード鍵の再設定を申請できるが、
数日かかるうえ手間がかかる。

参考: リリース鍵の SHA-1（Google Books API キーの制限に登録する値）

```
3C:97:33:67:F3:74:BE:DD:32:25:27:48:70:B8:29:85:94:40:FB:F5
```

いつでも次のコマンドで確認できる。

```
keytool -list -v -keystore keystore/yomumemo-upload.jks -alias yomumemo-upload
```

## 6. アプリ内商品を登録する

**収益化 → 商品 → アプリ内アイテム → 商品を作成**

| 項目 | 値 |
|---|---|
| 商品ID | `yomumemo_premium_lifetime` |
| 種類 | 管理対象のアプリ内アイテム（非消費型） |
| 名前 | ヨムメモ プレミアム |
| 説明 | store-listing.md を参照 |
| 価格 | ¥900 前後を推奨 |

**商品IDはコードに埋め込んである**（`BillingManager.PREMIUM_PRODUCT_ID`）。
違う ID で登録すると商品が取得できず、購入ボタンが押せないままになる。

登録したら **有効** にするのを忘れないこと（作成しただけでは無効のまま）。

> 商品を登録できるのは、**お支払いプロファイルの作成が完了してから**。
> 完了していないとメニュー自体が出ない。

## 7. 内部テストで動作を確認する

組織アカウントではクローズドテストは**不要**だが、
**内部テストは必ず通すこと**。理由は、ここでしか確認できないことがあるため。

1. **テスト → 内部テスト → 新しいリリースを作成**
2. `app/build/outputs/bundle/release/app-release.aab` をアップロード
3. テスターに自分のアカウントを追加し、オプトインURLからインストール
4. **設定 → ライセンステスト** に自分のアカウントを追加（購入が実際に課金されなくなる）

**ここで必ず確認すること:**

- [ ] 実際の本のバーコードを読み取って登録できる
      （**エミュレータでは検証不可能。実機でのみ確認できる**）
- [ ] 引用のカメラ取り込み（OCR）が動く（**これも実機でのみ**）
- [ ] 購入画面に価格が表示される
- [ ] 購入が完了し、プレミアム機能が解放される
- [ ] アプリを消して入れ直しても「購入を復元する」で戻る

> **ローカルにインストールした APK では課金は動かない。** 必ず内部テスト経由で。
> 内部テストはテスター数の下限が無く、自分1人でも即座に配信できる。

## 8. 製品版を公開する

クローズドテストは対象外なので、**製品版アクセスの申請は不要**。

1. **製品版 → 新しいリリースを作成** → `app-release.aab` をアップロード
2. リリースノートを書く（初回は「最初のリリースです。」程度で足りる）
3. 審査へ提出

初回の審査は数日かかることがある。

---

## 更新するときの手順

1. `app/build.gradle.kts` の `versionCode` を +1、`versionName` を更新
2. `./gradlew :app:bundleRelease`
3. 生成された AAB をアップロード

**`versionCode` を上げ忘れると、同じ番号のためアップロードが弾かれる。**

## よくある詰まり

| 症状 | 原因 |
|---|---|
| 組織確認で差し戻される | 屋号・住所の表記が開業届／D-U-N-S と食い違っている。番地の書き方まで揃える |
| アプリ内商品のメニューが出ない | お支払いプロファイルが未完成 |
| 購入ボタンが押せない | 商品が未登録・未有効、または商品IDの不一致 |
| 購入画面で「アイテムは購入できません」 | 内部テスト経由でインストールしていない |
| 表紙が出ない | Google Books API キーが未設定、または SHA-1 の登録漏れ |
| デバッグ版で表紙が出ない | デバッグ版のパッケージ名は `jp.yomumemo.app.debug`。両方の登録が必要 |
| AAB がアップロードできない | `versionCode` を上げ忘れている |
